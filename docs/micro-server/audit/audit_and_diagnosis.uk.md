## 1. Загальне резюме

Проведено комплексну діагностику хмарного середовища Google Cloud `evabot-agent-server`. В інфраструктурі задіяні два активні екземпляри Compute Engine:
1. **`evabot-agent-vm`** у Франкфурті (`europe-west3-a`) — потужний обчислювальний вузол (`c3-standard-8`, 32 ГБ DDR5 RAM, 100 ГБ NVMe).
2. **`evaline-micro-vm`** в Айові (`us-central1-a`) — веб-шлюз та маршрутизатор доменів (`e2-micro`, 1 ГБ RAM + активований swap 2 ГБ, 20 ГБ диск), на якому працює веб-сервер Caddy і хостяться сайти, включаючи `evabot.online`.

Попередня реалізація у `/var/www/evabot.online` була демонстраційним макетом із фіктивними відповідями без реального підключення до API Gemini. Попередній код архівовано на мікросервері (`/var/www/evabot.online_pre_gemini_backup_20260903_150219.tar.gz`) та локально (`legacy_archive/evabot_v001_initial_snapshot.tar.gz`).

## 2. Інвентаризація серверів та аналіз ресурсів

### 2.1 Сервер 1: `evabot-agent-vm` (Обчислювальний вузол у Франкфурті)
- **Зона:** `europe-west3-a`
- **Тип машини:** `c3-standard-8` (8 vCPU Intel Sapphire Rapids, 32 ГБ DDR5 RAM)
- **Зовнішній IP:** `34.179.253.183`
- **Внутрішній IP у VPC:** `10.156.0.2`
- **Диски:**
  - `persistent-disk-0`: 50 ГБ завантажувальний NVMe (`/`)
  - `persistent-disk-1`: 50 ГБ підключений NVMe (`/data`)
- **Операційна система:** Debian 12 (Bookworm), ядро Linux 6.1
- **Активні служби:** Nginx, Code-Server (`code-server@evabot.service`), Tailscale, служба SSH
- **Використання ресурсів:** Навантаження CPU 0.00, вільна оперативна пам'ять ~30 ГБ.

### 2.2 Сервер 2: `evaline-micro-vm` (Веб-сервер та доменний шлюз в Айові)
- **Зона:** `us-central1-a`
- **Тип машини:** `e2-micro` (2 vCPU burstable, 1 ГБ RAM, налаштовано swap 2 ГБ)
- **Зовнішній IP:** `136.114.26.252`
- **Внутрішній IP у VPC:** `10.128.0.2`
- **Диски:**
  - `persistent-disk-0`: 20 ГБ SCSI (`/`, зайнято 3.9 ГБ, вільно 15 ГБ)
- **Операційна система:** Debian 12 (Bookworm), ядро Linux 6.12
- **Встановлені середовища:** Node.js v20.20.2, npm 10.8.2, Git 2.47.3, Python 3.11, веб-сервер Caddy
- **Активні служби:**
  - Веб-сервер Caddy (порти 80 і 443 з автоматичним отриманням сертифікатів Let's Encrypt TLS)
  - TigerVNC (`Xtigervnc` на порту 5901 з графічним середовищем XFCE4)
  - Агент вузла Tailscale
  - Служба SSH, systemd
- **Веб-домени, налаштовані в Caddy:**
  - `evabot.online` та `www.evabot.online` (каталог `/var/www/evabot.online`)
  - `evaline.website` та `www.evaline.website` (каталог `/var/www/evaline.website`)
  - `evaline.online` та `www.evaline.online` (каталог `/var/www/evaline.online`)
  - `evaline.network` та `www.evaline.network` (каталог `/var/www/evaline.network`)

## 3. Аналіз попередньої версії EvaBot

У каталозі `/var/www/evabot.online` знаходився початковий прототип (`v0.0.1`):
1. **Фіктивні відповіді:** Генерувався шаблонний текст замість реальних викликів до Gemini.
2. **Статичний Canvas:** Каркасна 3D-сітка обличчя та синтетичні графіки телеметрії.
3. **Відсутність функцій LLM:** Не було клієнта потокової генерації, перемикача моделей та збереження пам'яті діалогу.

## 4. Архітектурна карта нового модульного чату

1. **Подвійне середовище виконання:**
   - Універсальний скрипт на TypeScript, що працює в будь-якому терміналі (CLI REPL та аргументи) та веб-браузері.
2. **Інтеграція з Google AI Pro / Gemini API:**
   - Вибір моделей: `gemini-2.5-flash`, `gemini-2.5-pro`, `gemini-2.0-flash`, `gemini-1.5-pro`.
   - Потокова передача токенів через SSE / ReadableStream.
3. **Легковаговий демон для мікросервера:**
   - Споживання пам'яті менше 40 МБ RAM.
   - Маршрутизація через Caddy reverse proxy (`/api/*` на локальний демон).
4. **Тестування та логування:**
   - Автоматичні тести (`npm test`) та структуроване логування у файл і консоль.
