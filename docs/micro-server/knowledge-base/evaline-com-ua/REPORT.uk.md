## 3. Технічна реалізація та методологія

### 3.1 Обробка лінивого завантаження PageSpeed
Сервер використовує модуль Google PageSpeed (`mod_pagespeed`), який динамічно замінює `<img src="...">` на 1x1 GIF-заглушки (`/pagespeed_static/1.JiBnMqyl6S.gif`), переносячи справжній URL в атрибут `data-pagespeed-lazy-src`.
- **Рішення:** Розроблено спеціалізований препроцесор DOM, що перехоплює атрибути `data-pagespeed-lazy-src` та `data-src`, відновлюючи оригінальні абсолютні посилання на зображення до передачі контенту в конвертер Markdown.

### 3.2 Очищення структури HTML DOM
Для отримання чистого Markdown без технічного шуму:
- Видалено скрипти аналітики (Google Tag Manager, Google Analytics).
- Видалено віджети онлайн-чатів (віджети Binotel).
- Очищено модальні вікна, мобільні перемикачі меню та форми зворотного зв'язку з CSRF-токенами.
- Блоки консультації фахівців (`sotr-bl`) оформлено у вигляді охайних розділових блоків Markdown.

### 3.3 Перетворення посилань і тегів Base
- Коректно враховано теги `<base href="...">` на всіх доменах для точного визначення шляхів відносних посилань.
- Усі знайдені внутрішні посилання зведено до відносних шляхів `.md`, що забезпечує повноцінне офлайн-читання.

### 3.4 Структуровані метадані
Кожен файл містить стандартизований YAML frontmatter:
```yaml
---
title: "..."
description: "..."
url: "https://evaline.com.ua/..."
lastmod: "2024-08-29T16:07:02+03:00"
language: "uk"
language_name: "Ukrainian"
category: "b2b"
og_image: "https://evaline.com.ua/images/..."
file: "uk/b2b/eva-lysty.md"
---
```
