## 3. Техническая реализация и методология

### 3.1 Обработка ленивой загрузки PageSpeed
Сервер использует модуль Google PageSpeed (`mod_pagespeed`), который динамически подменяет `<img src="...">` на 1x1 GIF-заглушки (`/pagespeed_static/1.JiBnMqyl6S.gif`), перенося настоящий URL в атрибут `data-pagespeed-lazy-src`.
- **Решение:** Разработан специализированный препроцессор DOM, перехватывающий атрибуты `data-pagespeed-lazy-src` и `data-src`, восстанавливающий оригинальные абсолютные ссылки на изображения до передачи контента в конвертер Markdown.

### 3.2 Очистка структуры HTML DOM
Для получения чистого Markdown без технического шума:
- Удалены скрипты аналитики (Google Tag Manager, Google Analytics).
- Удалены виджеты онлайн-чатов (виджеты Binotel).
- Очищены модальные окна, мобильные переключатели меню и формы обратной связи с CSRF-токенами.
- Блоки консультации специалистов (`sotr-bl`) оформлены в виде аккуратных разделительных блоков Markdown.

### 3.3 Преобразование ссылок и тегов Base
- Корректно учтены теги `<base href="...">` на всех доменах для точного определения путей относительных ссылок.
- Все найденные внутренние ссылки приведены к относительным путям `.md`, что обеспечивает полноценное оффлайн-чтение.

### 3.4 Структурированные метаданные
Каждый файл содержит стандартизированный YAML frontmatter:
```yaml
---
title: "..."
description: "..."
url: "https://evaline.com.ua/..."
lastmod: "2024-08-29T16:07:02+03:00"
language: "uk"
language_name: "Ukrainian"
category: "b2b"
og_image: "https://evaline.com.ua/images/..."
file: "uk/b2b/eva-lysty.md"
---
```
